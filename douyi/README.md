# 斗文台 · douyi

> 两台机器，一张桌案。以理相争，以诗相和，以字相接。

一台 **AI 互斗观测装置**。不是聊天框，是一张赛席：两台 AI 分坐甲乙，一盏茶的时间，用**辩论**、**飞花令**或**成语接龙**决出胜负。发言逐字落墨，裁判退席写判词，最后落槌、盖印。

- **舌战**：同一命题，立论、驳论、结辩；四位辩手各有辩风。
- **诗战**：抽一字为令，轮流诵句；缺令字、重句、接不上即判负。
- **斗口**：上一句的末字，是下一句的首字；四字成语，首尾相衔，接不上即断。
- **两种引擎**：零配置的本地演示，或接任意 OpenAI 兼容模型（A、B、裁判可各用其模型）。
- **零构建**：原生 ESM、无框架、无依赖安装；一个 Node 文件同时托管静态站点与 SSE 代理。

## 开局

```bash
cd douyi
npm start          # http://127.0.0.1:8050/
npm test           # 51 项纯逻辑测试，Node 直跑，无需浏览器
```

需要 **Node.js 20+**。没有 `npm install`，也没有打包步骤——`package.json` 只提供 `start` 与 `test` 两个入口。

为什么要一个本地 Node 服务？两件事：

1. **静态服务无缓存**。这个项目的开发循环是「改文件 → 刷新」，`Last-Modified` 的启发式缓存会让 ES 模块过期，报出完全看不出原因的错。
2. **模型请求需要同源代理**。浏览器直接调模型商会遇到 CORS；而且把 API Key 放在前端直连，也不方便做统一的超时与流式转发。`/api/chat` 只负责把你的请求原样转给模型商，再把 SSE 原样流回来。

端口被占用时可以换一个：

```powershell
$env:PORT=8060; npm start
```

## 三种斗法

### 舌战 · Debate

| 赛制 | 阵数 | 流程 |
| :--- | :--- | :--- |
| 快辩 | 6 | A 立论 → B 立论 → A 驳论 → B 驳论 → A 结辩 → B 结辩 |
| 鏖战 | 10 | 加入两轮自由辩，短兵相接后再结辩 |

四位本地辩手：**墨守**（逻辑拆解）、**庄生**（以喻代辩）、**纵横**（气势压迫）、**温言**（共情说服）。本地演示引擎按人设写模板，在线模式则把同样的立场、赛制与全场记录交给模型。

裁判按 **立论 25 / 驳论 25 / 表达 25 / 风度 25** 落槌。在线裁判返回严格 JSON；本地裁判只做结构启发式评分，不冒充文学判断。

### 诗战 · Feihualing

选一个汉字作令，双方轮流接一句含令字的古诗词。

| 规则 | 说明 |
| :--- | :--- |
| 句数 | 八 / 十二 / 十六句，甲席先起 |
| 必须含令字 | 缺字即失律，可重吟一次 |
| 不得重复 | 席上出现过的句子不能再接 |
| 一句为限 | 一次只接一句，最长 24 个汉字 |
| 接不上 | 两次不合格或超过 90 秒，判负 |
| 库中 / 待考 | 本地诗库命中为「库中」；库外名句标为「待考」，仍可继续 |

「待考」是有意留的缝：437 句的本地库不可能覆盖所有古诗词，在线模型接出库外名句时，直接判伪作太傲慢；但也不能假装它已被核实。所以它会被明确标成待考，并在「准确」一项上略低于可核实的库中句。

本地演示诗库 **437 句**，含 14 个常用令字（月、花、风、春、山、水、云、酒、雪、江、秋、人、天、夜），也可自定一字（本地库中至少四句）。四位诗人：**青莲**（豪放）、**易安**（婉约）、**摩诘**（山水）、**玉溪**（奇崛）；本地取句会按人设偏好加权。

裁判按 **准确 30 / 广博 30 / 意境 20 / 机敏 20** 评胜负。

### 斗口 · 成语接龙

选一个汉字作起字，第一回必须接一个以此字开头的四字成语；之后每一回，以上一句的**末字**作为下一句的**首字**。

| 规则 | 说明 |
| :--- | :--- |
| 回数 | 八 / 十二 / 十六回，甲席先起 |
| 四字为限 | 每次只接一个四字成语，首字必须严格相同 |
| 不取谐音 | 「意」只能接「意」，不接同音字 |
| 不得重复 | 席上出现过的成语不能再接 |
| 接不上 | 两次不合格或超过 90 秒，判负 |
| 库中 / 待考 | 本地词库命中为「库中」；库外成语标为「待考」，仍可继续 |

本地成语库 **1222 条**。为了让本地对局真的能一路接下去，启动时会从词库中自动剪出一个**闭合可接核心 290 条**：核心里的每个末字，都能在核心内找到下一句的开头。本地词客优先从核心取词，尽量避开无路可接的死胡同；在线模型仍可接出库外成语，但会被标为待考。

四位本地词客：**书袋**（典故派）、**机锋**（急智派）、**市井**（俗语派）、**雅士**（清雅派）。本地取词会按人设的用字偏好与下一字的可接度加权。

裁判按 **准确 30 / 连贯 25 / 博闻 25 / 机敏 20** 评胜负。

## 本地推演 vs 在线模型

| | 本地推演 | 在线模型 |
| :--- | :--- | :--- |
| 联网 | 不需要 | 需要 |
| 辩论 | 人设模板 + 对手原句拆解 | 任意 OpenAI 兼容模型 |
| 诗战 | 本地诗库按人设取句 | 模型接句，本地校验 |
| 斗口 | 优先从可接核心取词 | 模型接龙，本地校验首字与重复 |
| 裁判 | 结构启发式评分 | 裁判模型返回 JSON 判词 |
| 适合 | 开箱即用、离线演示、测试 | 真正的模型对模型 |

在线模式在 **模型与席面** 里配置：

- API 地址（可填 `/v1` 基地址，也可直接填完整的 `/chat/completions` 地址）
- API Key（可留空，适用于 Ollama 等本地服务）
- 正方 / 甲席模型、反方 / 乙席模型、裁判模型
- 一键测试连接

内置 DeepSeek / OpenAI / Ollama 三个预设，其余接口填自定义地址即可。典型配置：

```text
DeepSeek  https://api.deepseek.com/v1   deepseek-chat
OpenAI    https://api.openai.com/v1     gpt-4o-mini
Ollama    http://localhost:11434/v1     qwen2.5:7b
```

**断线会兜底**：在线调用失败时，本局自动切换为本地推演继续，顶部出现提示条，判词里标明「在线中断 · 本地兜底」。不会把一局已经开席的比赛卡死在一次超时上。

### 密钥怎么走

```text
浏览器 localStorage
      │  POST /api/chat  { endpoint, apiKey, model, messages }
      ▼
本机 Node 服务 serve.mjs（127.0.0.1）
      │  POST {endpoint}/chat/completions  + Authorization
      ▼
模型服务商
      │  SSE 流
      ▼
serve.mjs 原样转发 → 浏览器逐字渲染
```

- 密钥只存在浏览器 localStorage；服务端不落盘、不写日志。
- 服务只绑定 `127.0.0.1`，不对局域网开放。
- `/api/chat` 限制请求体 2 MB，上游超时 180 秒。
- 浏览器端不把模型输出当 HTML 使用；所有发言、成语与判词都用 `textContent` 渲染。

### 一次接令的数据流

```text
选令字 / 起字 → 取一句
   │
   ├─ 本地推演：诗库或成语核心按人设偏好取句 → validatePoetryAttempt / validateChainAttempt
   └─ 在线模型：prompt → SSE 全量读完 → 抽取 → 校验
                                                     │
                            ┌────────────────────────┴──────────────────────┐
                            │ 命中本地库 → tagged 库中 + 作者/篇名或词条   │
                            │ 库外成句 → tagged 待考 + 仍计入本回合        │
                            │ 缺字 / 重句 / 首字不对 / 超长 → 允许一次重吟 │
                            └────────────────────────┬──────────────────────┘
                                                     ▼
                              battle.record*Turn → 判词
```

飞花令与接龙的在线响应不做逐字流式展示，而是先完整读完、抽取诗句或成语、校验，再在纸笺或字牌上逐字「落墨」。这样观众不会先看到一大段模型的解释，然后答案才被挑出来。

## 测试

```bash
npm test
```

51 项纯逻辑测试，覆盖：

- **诗库**：字段完整、文本唯一、无标点、常见令字句数下限、索引与查询。
- **诗令校验**：库中命中、库外待考、缺令字、重句、包含重句、超长、模型格式剥壳。
- **成语库**：四字、唯一、汉字、1222 条完整性、可接核心闭合、起字统计。
- **接龙校验**：首字严格相接、库中/待考、重句、错误首字、提示词不误伤「接」「答」开头的成语。
- **本地引擎**：随机数复现、四种辩手/词客产出、引用原文不破坏引号、评分区间与总分一致、本地取句去重、每个起字接满十二回。
- **状态机**：完整六阵/十阵顺序、交替接令、回末字传递、判负后拒绝继续、重复判负不覆盖。
- **SSE**：任意切片、CRLF、多行 data、`[DONE]`、错误提取。
- **裁判 JSON**：围栏/寒暄中抠 JSON、转义引号、分数夹取、缺胜者补判、缺判词拒绝。

测试不依赖浏览器、模型、网络或诗库/词库外部数据。

## 设计

- **纸与墨**：深墨底、稻纸色、朱砂 / 青玉 / 泥金三种语义色。标题用宋体，诗笺用楷体，字牌用宋体，数据用等宽体。
- **诗笺与字牌**：飞花令的接句是竖排纸笺，令字朱砂高亮；成语接龙是一排四张纸牌，首字朱红、末字青玉，标明这一回「承」哪一个字、下一回「启」哪一个字。
- **落槌**：裁判退席评议会显示一枚「评」印；判词页的「胜 / 和」印有落章动画。
- **无外部素材**：没有字体文件、图片素材或音频文件；纹理是 SVG 噪声，音效是 WebAudio 现场合成，默认关闭。
- **可访问性**：原生 `<dialog>`、`aria-live` 状态、显式焦点样式、`prefers-reduced-motion` 降级、移动端无横向溢出。
- **本地优先**：设置、往战摘要、密钥都在本机；没有账号、没有服务端数据库。

## 已知边界

- **本地辩手是模板，不是模型**。它负责把比赛打起来、把论点和节奏演示清楚；真正的模型对模型请接在线模式。
- **本地裁判是启发式**。它按结构、交锋词、篇幅、取句广度等信号评分；它不代表文学判断。在线模式下裁判模型会写真正的判词。
- **诗库/成语库不是全集**。437 句诗、1222 条成语是手编的常用句库；库外内容只能标待考，不能替它背书。接龙核心 290 条是为了让本地局能持续，在线模型不受这个核心限制。
- **接龙不取谐音**。这是为了可验证性做的取舍；同一个音但不同字，不算接上。
- **往战只存摘要**。最多 12 局，保存在 localStorage；完整对局记录不落盘。刷新即散席。
- **密钥在 localStorage**。这是本地工具的便利选择，不是多用户产品的安全模型。共用电脑请在使用后清除密钥。
- **在线模型有自己的政策**。斗文台只负责转发与编排，不替模型商的内容政策做承诺。

## 诗库与成语库

本地诗库收录 437 句公共领域的古诗词，字段包括句子、作者、篇名、朝代、体裁（诗 / 词 / 曲）。以「月」「花」「风」「春」「山」「水」「云」「酒」「雪」「江」「秋」「人」「天」「夜」为常用令字，也可自定任意在库中至少出现四次的汉字。

本地成语库收录 1222 条四字成语。它会自动剪出一个闭合的可接核心（当前 290 条），用于本地词客取词与起字统计；完整 1222 条仍参与在线校验。

手工辑录难免有误；如果发现诗句的句子、作者、篇名有出入，或成语不是四字/有重复，直接改 `src/data/poetry.js` 或 `src/data/idioms.js`，测试会守住格式、重复与接龙核心的闭合性。
